# Снятие блокирующих заявок сверяется по объёму с обеих сторон

Вторая вставка — активные заявки из QUIK — содержит пять колонок: торговый счёт,
код инструмента, номер заявки, направление и количество. Снимаются все активные
заявки по закрываемому контракту, независимо от стороны: продажа связывает
контракты и мешает закрытию, покупка при исполнении увеличивает поставочное
обязательство.

## Considered Options

Минимальный набор «счёт + номер заявки» отвергнут. Без инструмента нельзя
убедиться, что снимается заявка по закрываемому контракту, а снятие чужой заявки
необратимо: она теряет очередь в стакане. Без направления и количества нельзя
отличить «заявок было две, обе сняли» от «заявок было три, про одну не знаем» —
второе означает отвергнутое закрытие и поставку.

## Consequences

Сумма количеств снимаемых заявок сверяется с «Акт. покупка» и «Акт. продажа»
соответствующей строки позиций; расхождение показывается явно. Заявки, для
которых нет закрываемой позиции, в транзакции не превращаются. Транзакции
снятия ставятся непосредственно перед закрытием своей позиции и делят с ним
сквозную нумерацию `TRANS_ID`. Гарантии, что снятие обработается раньше ввода,
торговая система не даёт — при отбое части закрытий сценарий повторяется
генерацией без снятий.

Снятие пишется универсальным диалектом — `ACTION=Снятие заявки;Номер заявки=…`,
без кода инструмента и счёта; строка получена выгрузкой из самого терминала.
Номер заявки обрабатывается только как текст: реальный номер
`2034815342882082294` — девятнадцать знаков, что превышает точность числа
в JavaScript и при разборе числом дало бы снятие чужой заявки либо ничего.
